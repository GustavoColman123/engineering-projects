# Problems and Debugging — Pico Resilience Monitor v0

This document records the main problems found during the development of the v0.1 functional prototype and how each one was diagnosed and solved.

The goal is not only to show the final working circuit, but also to document the engineering process behind it.

---

## 1. Unstable LDR Readings With 10kΩ Resistor

### Problem

The LDR was initially connected as a voltage divider using a 10kΩ resistor:

```text
3V3 ── LDR ── GP26_A0 ── 10kΩ ── GND
```

However, the ADC values stayed compressed around:

```text
300–500
```

The value was unstable and did not react clearly to changes in light.

Covering the LDR or shining light on it produced only small variations.

### Initial Suspicion

At first, the possible causes were:

```text
LDR incorrectly placed
Wrong ADC pin
Bad jumper connection
Wrong breadboard row
Incorrect 3.3V or GND connection
Damaged LDR
Code reading the wrong ADC channel
```

### Diagnostic Test

To check whether the Pico ADC was working, the LDR was temporarily replaced with a potentiometer connected to GP26_A0.

The potentiometer test worked correctly:

```text
Turning the potentiometer one way increased the ADC value.
Turning it the other way decreased the ADC value.
```

### Conclusion

This confirmed that:

```text
GP26_A0 was working
The ADC was working
The firmware was reading the correct channel
The serial output was working
```

Therefore, the problem was not the Pico or the code.

The problem was in the LDR voltage divider.

### Final Diagnosis

The 10kΩ fixed resistor was not appropriate for the resistance range of the LDR under the available lighting conditions.

With 10kΩ, the voltage at GP26_A0 stayed too low and too compressed.

### Solution

The fixed resistor was changed from 10kΩ to 100kΩ.

Final working circuit:

```text
3V3 ── LDR ── GP26_A0 ── 100kΩ ── GND
```

### Result

After changing to 100kΩ, the ADC range became much wider and more useful:

```text
Lamp off / low light: ~250–320
Strong nearby lamp:  ~3600+
```

This confirmed that the LDR was working correctly once the voltage divider was properly dimensioned.

## 2. Confusion Between 3V3 and 3V3_EN

### Problem

At one point, the real 3.3V pin was already being used by the LDR circuit, so `3V3_EN` was mistakenly considered as a replacement power pin.

When `3V3_EN` was used, the system shut down or became unstable.

### Cause

`3V3_EN` is not a normal 3.3V output.

It is the enable pin for the Pico's 3.3V regulator.

Using it incorrectly can disable the regulator or cause unstable power behavior.

### Solution

A proper 3.3V rail was created on the breadboard:

```text
Pico 3V3 → red breadboard rail
Pico GND → blue breadboard rail
```

The LDR, thermistor, and LCD were then powered from the shared 3.3V rail.

### Final Rule

Correct:

```text
Use 3V3 as the 3.3V power source.
```

Incorrect:

```text
Do not use 3V3_EN as a power source.
Do not use VBUS for ADC sensor circuits.
Do not use VSYS for this sensor setup.
```

## 3. LED Connected to the 3.3V Rail

### Problem

One LED, especially the blue LED, was accidentally connected to the 3.3V power rail.

Because the 3.3V rail is always powered, the LED stayed on permanently.

### Why This Was a Problem

The LED produced light near the LDR and contaminated the sensor reading.

Instead of measuring the external environment, the LDR was partially measuring light generated by the circuit itself.

### Diagnosis

The LED stayed on regardless of the program state.

That meant it was not being controlled by a GPIO pin.

### Solution

The LED was removed from the 3.3V rail and connected properly as a GPIO-controlled output:

```text
GP17 ── resistor ── LED ── GND
```

### Final Rule

The 3.3V rail is for constant power.

GPIO pins are for controlled outputs.

Correct:

```text
GPIO → resistor → LED → GND
```

Incorrect:

```text
3V3 → resistor → LED → GND
```

unless the goal is to keep the LED permanently on.

## 4. Button Debouncing

### Problem

A mechanical push button does not produce a perfectly clean signal when pressed.

It can rapidly switch between high and low for a short time due to mechanical bouncing.

### Solution

A simple debounce delay was added after detecting a button press:

```c
sleep_ms(50);
```

The program also waits until the button is released before accepting another press.

### Result

The button reliably changes the system mode one step at a time:

```text
NORMAL → URBAN_HEAT → TYPHOON_ALERT → NORMAL
```

## 5. Need for Hysteresis

### Problem

The raw ADC values from sensors can fluctuate slightly.

If a threshold is too simple, the system can rapidly jump between states such as:

```text
LOW_LIGHT ↔ NORMAL_LIGHT
NORMAL_LIGHT ↔ HIGH_LIGHT
```

This creates unstable behavior.

### Solution

Hysteresis was added for both light and temperature.

For light:

```text
LOW enters below 700
LOW exits above 900

HIGH enters above 2500
HIGH exits below 2200
```

For temperature:

```text
TEMP_HIGH enters above 2200
TEMP_HIGH exits below 2000
```

### Result

The system became more stable and less sensitive to small ADC fluctuations.

## 6. Termistor Raw Reading Instead of Celsius

### Current Limitation

The thermistor is currently used through raw ADC values, not calibrated temperature in degrees Celsius.

Observed values:

```text
Resting temperature: ~1850
Held between fingers: ~2360
After release: returns near ~1860
```

### Reason

The first goal was to validate that the thermistor responds to temperature changes.

Converting to Celsius requires additional assumptions:

```text
Nominal thermistor resistance
Beta coefficient
Reference temperature
Exact resistor value
ADC voltage reference
```

### Future Improvement

A future version may convert ADC values to approximate Celsius using the thermistor equation or Steinhart-Hart approximation.

## Summary of Key Lessons

The main debugging lessons were:

```text
1. A working sensor still needs a correctly dimensioned voltage divider.
2. ADC problems should be isolated using known-good analog sources, such as a potentiometer.
3. 3V3_EN is not a normal power output.
4. LEDs placed near light sensors can contaminate measurements.
5. Hysteresis is necessary for stable threshold-based systems.
6. Raw ADC values are useful for prototypes, but calibrated measurements require additional modeling.
```

The most important result was the LDR debugging process. The problem was not solved by guessing, but by isolating the ADC, testing with a potentiometer, identifying the voltage divider issue, and changing the fixed resistor from 10kΩ to 100kΩ.
